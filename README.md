## 上游依赖图

解析任务可挂上游依赖，依赖列表、读盘详情、依赖策略三处贯通，约束全部由后台强制。

- **依赖声明**：下游任务至少声明一个上游，空依赖不许保存；禁止自依赖与成环（`JobDependency` 有向边，下游→上游唯一）。
- **开析前置**：上游仍在读盘（未到「已解析待入库/已入库」）时，下游读盘入口在页面上保持不可见，后端同样拒绝开析，状态写入读盘详情。
- **依赖走法（上游挂掉后下游去向）**：在「依赖列表」页落定，二选一，一经落定当天不许再改：
  - `进等待舱`：下游进入等待舱，普通开析封死，须人工确认并填写强析缘由后强行开析；
  - `取消并标依赖中断`：下游一律取消并标注「依赖中断」，无强析通道。
  - 点读盘的走法与策略不符时一律拦截，事件记为「走法拦截」。
- **争用**：两人同时点下游读盘，行锁内只留先到；后来者记「争用失败」事件。
- **读盘详情**：上游态、强析缘由、进舱/中断、争用失败与走法拦截均以事件流水呈现。
- **依赖列表**（`/dependencies/`）：按下游任务展示上游态、是否齐套、等待舱标记、中断数与当前走法名。

### 数据模型

| 模型 | 说明 |
|------|------|
| `ParseJob` | 解析任务，新增 `force_reason`（强析缘由）与「等待舱 / 依赖中断」状态 |
| `JobDependency` | 下游→上游依赖边，`(downstream, upstream)` 唯一 |
| `DependencyPolicy` | 单例依赖走法，`locked_date` 记录落定日，当日锁定 |
| `JobEvent` | 读盘详情事件流水（开析/强析/进舱/中断/争用失败/走法拦截/依赖设置） |
